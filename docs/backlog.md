# Backlog

## P1 — Production Volume size limit
Railway Trial plan ограничивает volume 500 MB. Текущий объём БД на 
полном импорте 1 проекта (tempus.ru, 5 источников, 1 период) — ~1 GB.
Не влезает.

Текущее решение: ужать данные (см. ниже). Не отвечает требованию 
хранить полную raw-историю.

Возможные пути:
- Upgrade Railway Hobby ($5/мес) → volume до 5 GB
- Перенос БД на внешнее хранилище (S3 + DuckDB httpfs, или Postgres)
- Не хранить query_facts полностью — оставлять только query_unified
- Партиционирование query_facts по периодам с архивацией старых

Прийти к решению до второго проекта или второго периода tempus.ru.

## P2 — GSC Queries.csv лимит 1000 строк
GSC UI экспорт обрезает топ-1000 запросов. SUM(Queries.clicks)=250 
против Chart.total=481 за день. Теряется ~48% хвоста.

Текущее решение: gsc_daily_totals хранит полные значения для контроля.
В дашборде показывать рядом "детализировано / всего за день".

Возможные пути:
- Перейти на GSC API (без лимита, нужен OAuth/service account)
- Сегментировать экспорт по дням (за месяц = 30 файлов вместо одного)

## P3 — y.metrika "Поисковая фраза" = "Не определено"
Метрика скрывает реальные поисковые запросы пользователей (privacy).
Данные о визитах привязаны только к URL, не к запросу.

Текущее решение: в query_facts из Метрики query=NULL, url=полный путь.
Связь с поисковыми запросами строится через URL → Topvisor/Webmaster.

Возможные пути: нет — это ограничение Метрики.

## P4 — y.direct невозможна группировка "Москва + поисковый запрос"
В Мастере отчётов Яндекс.Директа фильтр "Регион" несовместим с 
группировкой "Поисковый запрос". Можно выгрузить либо по запросам 
без региона, либо по региону без запросов.

Текущее решение: импортируем как russia_mobile (без фильтра региона).
В БД помечено region=russia, нельзя складывать с moscow_* из других 
источников.

Возможные пути:
- Direct API (поддерживает оба измерения одновременно)
- Создать отдельную кампанию на Москву → выгружать на уровне кампании

## P5 — Производительность rebuild_query_unified
На 7M строк rebuild занимает 8.3s. На 5 проектах × 12 месяцев ≈ 100M 
строк — будет ~2 минуты. Сейчас приемлемо, в будущем — узкое место.

Возможные пути:
- Incremental rebuild (только новые import_id)
- Materialized view с auto-refresh
- DuckDB COPY вместо INSERT в pivot
